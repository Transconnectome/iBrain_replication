# iBrain Replication Specification

arXiv 2609.06960v1 (2026-09-07). No public code. We implement from the paper alone.
Written 2026-09-23, updated 2026-09-28. Code: Wooseok Choi. Kyuhyung Lee: data survey (division of work discussed 9/24).

## 0. Scope

**What we do now (spike-only baseline).** Implement the model as described in the paper faithfully, confirm the pipeline runs end to end on MC-Maze alone, and produce downstream numbers. M1–M4.
**All code gets written.** Everything described in the paper, including the iEEG encoder, decoder, and MSE loss (M5) and the 1:1 alternation (M6), is implemented and **verified on synthetic data**. Only real-data runs are deferred until access and compute are secured (AJILE12, SWEC, the 7,160-hour M7). The reason is data access, unrelated to DIVER.
**Reproducing the numbers is not the goal.** The paper does not state the number of seeds and has no code. Our deliverables are (1) code that works as the paper describes, (2) the list of decisions (Section 2), and (3) run records that keep seeds, checkpoints, and configs (U26). Gaps against the paper's numbers are only reported.

The replication has two deliverables. (1) Working code. (2) **The list of items not stated in the paper that we decided ourselves** (Section 2). The second is more valuable to hand to the team.

## 1. What the paper states

### 1.1 Input representation

| Item | Value |
|---|---|
| Window | 1 s |
| Patch | 100 ms × 10 ($S = 10$) |
| iEEG | 500 Hz, $P_{\text{iEEG}} = 50$ samples per patch. One channel is one sequence |
| Spike | **20 ms binning**, $P_{\text{spike}} = 5$ counts per patch. One unit is one sequence |
| Tensor | $X^m \in \mathbb{R}^{C_m \times S \times P_m}$ |
| Padding | Padding along the channel axis; a binary valid mask $V_c$ excludes padded positions from attention, pooling, and loss |

### 1.2 Per-signal encoder $f_m: \mathbb{R}^{P_m} \to \mathbb{R}^d$

| | Structure |
|---|---|
| $f_{\text{iEEG}}$ | Temporal CNN adapter + **residual linear path** (CNN captures local waveforms; the linear path maps samples directly into token space) |
| $f_{\text{spike}}$ | MLP |

Applied independently to each patch. Output $H^m \in \mathbb{R}^{C_m \times S \times d}$.

### 1.3 Embedding

$$Z^m_{c,s} = H^m_{c,s} + e^m_{\text{type}} + e^{\text{time}}_s$$

$e^m_{\text{type}}$ is one per signal type; $e^{\text{time}}_s$ is one per patch position. **No term depends on the channel index $c$.**

### 1.4 Backbone (criss-cross ST attention)

Each block runs two stages in order.

1. Channel attention: independently for each time index $s$, over the channel axis. $\tilde Z^m_{:,s} = \text{Attn}_{\text{ch}}(Z^m_{:,s})$
2. Temporal attention: independently for each channel $c$, over the time axis. $Z^m_{c,:} = \text{Attn}_{\text{time}}(\tilde Z^m_{c,:})$

A **learned relative time bias** is added to the temporal attention logits. Pre-norm, residual, FFN.

| Hyperparameter | Value |
|---|---|
| Layers | 6 |
| $d$ | 256 |
| Heads | 8 |
| FFN | 1024 |
| dropout | 0.1 |

Output $U^m = F_{\text{ST}}(Z^m) \in \mathbb{R}^{C_m \times S \times d}$. The backbone is **shared** by both signal types.

### 1.5 Pretraining objective

**Masked reconstruction.** Mask $M \in \{0,1\}^{C_m \times S}$, **50%** of valid tokens. Masking is applied in raw signal space ($\tilde x = (1-M)x$) before the encoder. The decoder $g_m$ is a 2-layer MLP, $d \to P_m$. The loss is computed only at masked valid positions.

- iEEG: target is the **channel-normalized waveform patch**. $\ell = \frac{1}{P}\|\hat x - x\|_2^2$
- Spike: $\lambda = \text{softplus}(\hat x) + \epsilon$, Poisson NLL

**channel-view alignment.** From the same segment, two views each with **about 80%** of the valid channels, **75% overlap**, **at least 2 channels**. Each view → encoder → backbone → global pooling over valid tokens → segment representation $r_1, r_2$ → projection $q$ (**128-dim**) → prediction $p$. SimSiam:

$$\mathcal{L}_{\text{align}} = \tfrac12 D(p_1, \text{sg}(q_2)) + \tfrac12 D(p_2, \text{sg}(q_1)), \quad D = -\cos$$

**Schedule.** iEEG batches and spike batches **alternate 1:1**. One type per step. $\mathcal{L}_t = \mathcal{L}^{m_t}_{\text{rec}} + \mathcal{L}^{m_t}_{\text{align}}$.

### 1.6 Training setup

| | Value |
|---|---|
| epoch | 30 |
| Optimizer | AdamW, lr $5\times10^{-4}$, wd $5\times10^{-2}$ |
| clip | 1.0 |
| Schedule | warmup 2,000 steps → cosine → $1\times10^{-5}$ |
| Compute | 8 GPUs, batch 32 per GPU per type (ours: 256 per step on one GPU, cut by unit count, U33) |

### 1.7 Data

| | Pretraining | Downstream |
|---|---|---|
| iEEG | AJILE12 + SWEC, 3,950 h | Brain Treebank (Pitch, Volume, Onset, Speech), AUC |
| Spike | Neural Pile, 3,209 h | MC-Maze, Area2-Bump, Perich T-CO, T-RT, $R^2$ |

### 1.8 Downstream protocol

- Spike: **80/20** split within each dataset. **Full-parameter fine-tuning** + lightweight task head
- iEEG: BrainBERT/PopT subject-specific protocol (fine-tune per subject)
- Paper numbers: MC-Maze 0.914 / Area2 0.903 / T-CO 0.785 / T-RT 0.692. Frozen: MC-Maze 0.904, Area2 0.867

(d) Electrodes: the clean Laplacian rule (corrupted names removed, then both shaft neighbours required; 72 to 205 per subject); **Main condition: no notch and no re-reference**, the same input as pretraining (decided 2026-10-05, Kyuhyung Lee, after the PR #3 review asked why notch and Laplacian exist only downstream; to be confirmed with Dongyeop). Pretraining adds neither (AJILE12 is released already notched and median-referenced, SWEC band-passed), and a shaft Laplacian cannot be built for SWEC (no channel metadata) or the AJILE12 grids, so the downstream input follows pretraining rather than the reverse. **PopT variant** (`reref: laplacian`, `notch_hz: [60, ..., 360]`; the `treebank_popt` entry of `paper.yaml`, run only when `--dataset` names it): notch at 60 Hz and harmonics to 360 Hz (iirnotch, Q 30, causal as PopT), then Laplacian re-reference (minus the mean of the two neighbouring contacts on the shaft). Electrodes are the clean Laplacian set in both conditions, so the channel set does not change with the condition. (e) Resampled 2048 → 500 Hz (polyphase, up 125, down 512), then U4 normalization over the whole trial (`stat_seconds` gives chunks; it must be set to the pretraining unit once U4 is fixed). In each statistics chunk a channel is left out by the pretraining rule (`data_ieeg.usable_channels`, U31: under 30 s of finite samples, or scale below 1e-3 of the chunk's median channel scale); such a channel is set to 0 in that chunk and carries `channel_ok` False, which `collate_treebank` turns into `valid` False, so the model treats it exactly as a padded channel (excluded from channel-attention keys and from the heads) and every other channel keeps its position (the flatten head needs fixed positions). This equals the pretraining streams leaving the channel out of the block (`test_invalid_channel_equals_absent_channel`); 0 with `valid` True would instead show the model a constant channel it never sees in pretraining. Windows outside the recording, with a non-finite sample in a kept channel, or with no kept channel are dropped, and the counts are printed per trial and task (review of PR #3, 2026-10-05: three neighbouring flat contacts gave a Laplacian scale near 0 and values up to ~2e6). (f) **Split: per subject, test = the PopT test trial, train = the subject's other trials** (7 subjects: 1, 2, 3, 4, 6, 7, 10; sub_5, sub_8, sub_9 have one trial and are not evaluated). `mode="popt"` gives the PopT code's split instead: only the test trial, 80/10/10 at random. (g) `read_trials` reads and filters a trial once for all four tasks; `cache_dir` keeps the arrays as memory-mapped `.npy`; the cache name hashes every argument and the code (`code_version`: this file and the `data_ieeg` functions it uses), so a cache from other code is never loaded | The paper states only the four tasks, AUC, and "the subject-specific evaluation protocol of BrainBERT and PopT, where the model is fine-tuned on a subset of recordings from each subject and evaluated on the remaining held-out recordings"; all iEEG is "resampled to 500 Hz" and the model input is 1 s. (b), (d) are the PopT code (`write_multi_subject_multi_channel.py`, `trial_data_reader.py`, `h5_data_reader.py`); BrainBERT's `finetuning_template.yaml` has the same Laplacian, notch and test trials. (c) PopT and BrainBERT centre a 5 s window on the onset (delta = −2.5 s); iBrain's input is 1 s, so we keep the centring and shorten it. (f) The PopT code splits examples of the test trial at random (`tasks/utils.py`), which does not match the iBrain sentence; the sentence names held-out recordings, so the held-out trial is the default and the PopT split is kept as a variant. Survey 2026-10-03: all 26 trials on the lab server; every selected electrode exists and has both neighbours. The rule, like PopT's list, still holds 9 electrodes flagged in `corrupted_elec.json` (sub_2: RT3aHa2, RT3aHa3, RT2aA11; sub_7: RF2I14, RF2I15; sub_10: F10Fa5, F10Fa6, F10Fa7, F10Fa13), because BrainBERT subtracts the raw names (`RT3aHa2*`) from cleaned labels; kept by default to match the protocol, `drop_corrupted=True` removes them and their Laplacian users. ## 6. How to run

```bash
# Local verification (synthetic data, tests take about 2 min; the iEEG conv adapter is slow on CPU)
.venv/bin/python -m pytest -q
.venv/bin/python scripts/pretrain.py --config configs/tiny.yaml --seed 0 --out runs/tiny_s0
.venv/bin/python scripts/finetune.py --config configs/tiny.yaml --ckpt runs/tiny_s0/final.pt --out runs/ft_tiny --dataset synthetic

# Lab server (GPU jobs go through Slurm only)
sbatch scripts/slurm/pretrain.sbatch configs/paper.yaml 0 runs/spike_s0 --spike-only   # M3, seeds 0, 1, 2 separately
sbatch scripts/slurm/pretrain.sbatch configs/paper.yaml 0 runs/joint_s0                # M6, spikes + AJILE12 + SWEC
# Downstream (M4, M5): datasets are listed under finetune.datasets in the config; --dataset picks some (default: all).
# GPU: wrap in an sbatch script under scripts/slurm/ like pretrain.sbatch
python scripts/finetune.py --config configs/paper.yaml --ckpt runs/joint_s0/final.pt --out runs/ft_s0 --dataset mc_maze
python scripts/finetune.py --config configs/paper.yaml --ckpt runs/joint_s0/final.pt --out runs/ft_s0   # all eight benchmarks
```

The outputs of a single run are `out/meta.json`, `log.jsonl`, `ckpt.pt`, `final.pt` (pretraining) or `results.json` (downstream). When reporting, include the git hash, seed, and config from `meta.json` (U26).
